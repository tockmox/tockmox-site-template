# Your secrets

> **Nothing in this template applies what you put here, and that is a known bug
> as of v0.6.0.** The `site-secrets` Application that syncs this directory is
> generated by `tockmox-install.sh` and is missing from this hand-maintained
> template, so a site cloned from here commits its sealed secrets and never
> applies them. The symptom is `CreateContainerConfigError` on Authentik and
> Grafana. **Until this is fixed in 0.6.1**, either generate your site with
> `tockmox-install.sh` instead of cloning this template, or run
> `kubectl apply -f secrets/` yourself and accept that ArgoCD will not
> reconcile them.

SealedSecrets only. They are encrypted to **your** cluster's key, which is what
makes them safe to commit ... nobody else can decrypt them, including the
Tockmox project.

```bash
kubeseal --format yaml < my-secret.plain.yaml > my-secret.yaml
```

`secrets/*.plain.yaml` is gitignored so the unsealed input does not follow the
output into a commit.

Back up the sealed-secrets controller's private key somewhere that is not the
cluster it came from. Losing it makes every sealed secret in this repository
permanently unreadable.

Which secrets each layer expects, and how they are consumed:
`docs/administration/secrets.md` in the Tockmox repository.
